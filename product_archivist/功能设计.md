# Xudaai 产品档案工作台 — 产品与功能设计

## 产品目标

不论资料来自 Yupoo、1688、Excel 或人工整理目录，都必须经过同一套产品档案规范；采集器只负责取数和保存原始资料，不能自行定义最终目录结构。用户在产品工作台复核字段和文件，生成标准档案后再上传至 Xudaai。

## 主流程

工作台 → 采集与导入 → 产品复核 → 标准档案生成 → 上传 → 任务中心
                           ↕
                        AI 助手

1. 用户选择 Yupoo、1688/OpenCLI、Excel 或本地目录入口。
2. 软件创建可查询的下载/导入任务；来源解析器识别供应商、产品和资料关系。
3. 所有来源形成同一个“批次—供应商—产品”工作清单。
4. 产品复核显示字段、原始来源、主图和缺项。AI 只给有证据的建议，不自行猜值或静默覆盖。
5. 档案生成器按统一 schema 写入本地产品目录。
6. 用户选择产品上传；上传任务记录每个产品结果，可重试失败产品。

## 页面和职责

- 工作台：批次待办摘要和主流程入口。
- 采集与导入：Yupoo、1688/OpenCLI、Excel、本地目录四种来源。所有入口共用批次输出。
- AI 助手：可粘贴来源链接触发采集；选择产品后可对当前资料提问和提取字段，字段变更需用户确认。
- 产品复核：按供应商和产品查看、编辑、筛选缺项；保留字段证据。
- 标准档案与上传：生成标准目录，检查缺项和文件数，再上传到 Xudaai。
- 任务中心：下载/导入与上传分栏，统一搜索、分页、打开目录、重试与删除任务记录。
- 设置：模型地址、模型名称、API Key、本地输出目录、Xudaai URL 和账号。

## 标准档案

每款产品一个目录，批次和供应商仅作分组：

批次/
├─ 批次信息.json
└─ 供应商/
   ├─ 供应商信息.json
   └─ P-编号-产品名/
      ├─ 产品档案.json
      ├─ 图片/                 # 主图和副图，角色记入 JSON
      ├─ 视频/
      ├─ 规格/
      └─ 原始资料/             # 原始 Excel、PDF、Yupoo 信息、1688 信息等

产品档案.json 是产品字段和文件清单的机器主档案，保存 schema 版本、稳定产品 ID、产品编号、供应商、价格、MOQ、规格、箱规、重量、媒体清单、来源 URL、字段来源、缺失字段和复核状态。原始资料保留副本，永不作为 AI 指令。未知值留空并标记，不以常识补造。

## 合并和重采规则

- 采集批次与产品使用来源商品 ID/相册 ID 建立关联。
- 重采不直接覆盖已确认字段；空字段可补，新旧冲突进入人工核对。
- 原始下载保留；素材按内容哈希去重。
- AI 建议需预览、确认后写入字段，并记来源。
- 删除任务记录与删除本地目录是独立操作；默认仅删记录。

## 数据与任务

- 任务表保存任务类型、来源、输入链接/路径、状态、产品数、输出目录、结果详情及时间。
- 任务中心的下载栏包括采集和导入；上传栏包括 Xudaai 上传。
- 本地标准档案是上传重试的依据，上传任务保留逐产品成功/失败明细。
- 运行数据库与旧版文件名隔离，不导入旧界面状态或旧版批次。

## 交付检查点

1. 以真实 Yupoo 类目/相册确认采集结果能生成产品复核行。
2. 以本机 OpenCLI 的 1688 商品页确认字段、图片和输出归属。
3. 用多供应商、多产品 Excel 和嵌套人工目录验证归类。
4. 用 Xudaai API 确认产品目录、JSON 字段、索引与更新规则。
5. 验证重复采集不覆盖人工补录，失败上传可从任务中心重试。

第 4、5 项依赖真实账号和服务端数据，需在部署环境完成联调。
