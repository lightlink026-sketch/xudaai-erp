# 产品报价单与 PDF 功能规划

## 目标

在现有产品资料 AI 助手中增加可审阅、可保存、可下载的报价单流程。AI 用于查找产品资料和整理描述；价格、税费、运费、合计金额由结构化数据和程序计算。用户确认后才生成正式文件。

## 用户流程

1. 从 AI 对话里的“生成产品报价”或“生成 PI 形式发票”开始。
2. 在同一对话里输入产品型号、上传产品图片并补充客户信息；AI 检索已索引资料并逐步询问缺项。
3. 填客户、币种、有效期、贸易条款和交付信息。每个产品行填写型号、描述、数量、单价、单位、折扣和备注。
4. 选填运费、其他费用及其计价说明。页面即时计算行金额、折扣、费用和总额。
5. 检查产品信息和价格来源；未知字段标红或提示补齐。AI 建议的内容必须由用户确认。
6. 预览 A4 报价单，确认后保存草稿或生成 PDF；PDF 可重新下载，也可复制为新报价。

## 页面组成

- **报价单入口**：新增报价单、草稿、已生成报价单列表；支持按单号、客户、日期搜索。
- **报价编辑器**：客户和单据信息、产品明细表、费用区、备注/条款区、金额汇总。
- **资料选择器**：复用本地产品搜索和图片匹配；选择后引用产品型号、图片、描述和来源文件。
- **预览**：显示最终分页、页眉页脚和汇总；桌面和 NAS 浏览器行为一致。
- **模板设置**：公司名称、Logo、地址、联系方式、收款信息、默认币种/条款、报价单编号规则。
- DOCX 模板可放在 `data/templates/`（由 `TEMPLATES_DIR` 改目录）或从单据窗口上传；默认公司信息保存在 `quote_defaults.json`。

## MVP 范围

- 手工录入或从资料库选择产品；每个产品单价需用户填写或核对。
- 客户名称/地址、报价单号、日期、有效期、币种、贸易条款、付款条款、备注。
- 多产品行、数量、单价、折扣、行小计、其他费用、合计金额。
- 中文/英文报价单 PDF 下载；金额和数字由 Decimal 计算，保留币种小数位规则。
- 草稿保存、继续编辑、复制报价、删除草稿；生成后的 PDF 和报价数据可追溯。
- 保存每条产品描述、价格和费用的来源文件/人工录入标记；PDF 不把检索分数当作产品事实。

## 后续阶段

1. **价目表导入**：导入用户指定的 XLSX/CSV，预览列映射并校验型号、币种、价格、单位和生效日期；支持重复型号处理、更新记录和版本回溯。未经确认的导入不覆盖现有有效价格。
2. **PI/形式发票**：在报价单上复制生成 PI，补充收货人、付款节点、银行信息、装箱/交付条款；与报价单分别编号和归档。
3. **运费计算**：导入运费表并配置线路、目的地、重量/体积、计费重、阶梯价、最低收费、附加费和币种。每次计算列出输入值及采用的规则；规则不全就要求补充，不猜费率。
4. **团队/NAS**：加入登录和角色权限、报价归属/审计日志、共享模板与数据备份；NAS 部署仍通过环境配置指定数据目录。

## 关键数据结构

- `quotes`：报价单号、状态、客户信息、币种、日期、有效期、贸易/付款条款、费用、备注、创建/更新时间、PDF 文件路径。
- `quote_items`：报价单 ID、产品/型号、描述、数量、单位、单价、折扣、金额、图片/资料引用、价格来源和确认状态。
- `quote_templates`：公司抬头、Logo、联系信息、默认条款、编号前缀和模板设置。
- 后续增加 `price_lists` / `price_versions`、`freight_rules`，记录来源、导入时间、生效区间和规则版本。

金额需在服务端重新计算并校验；浏览器显示的合计不能作为权威值。草稿和 PDF 文件放在 `DATA_DIR` 下，数据库保存相对路径，便于整套迁移到 NAS。文件名使用单号并阻止路径穿越。

## API 草案

- `GET /api/quotes`：报价列表。
- `POST /api/quotes`：校验并保存草稿。
- `GET /api/quotes/{quote_id}`：载入草稿或已确认报价。
- `PUT /api/quotes/{quote_id}`：更新草稿。
- `POST /api/quotes/{quote_id}/pdf`：服务端重算金额、生成并保存 PDF，返回下载地址。
- `GET /api/quotes/{quote_id}/pdf`：下载已生成文件。
- `POST /api/quotes/{quote_id}/duplicate`：复制成新草稿。

报价单 PDF 由服务端从已确认数据生成，模板采用可配置 HTML/CSS 打印版式或 PDF 绘制组件，并为 Docker/NAS 镜像提供中文字体。避免依赖某一台 Windows 电脑的系统字体。

## 准确性与使用边界

- AI 可协助找产品、生成描述草稿、定位价目表行；不得自动编造价格、库存、重量、运费或交易条款。
- 价格表检索结果需展示来源文件、工作表/行号或页码、生效日期和币种；来源不明确时要求人工录入。
- 折扣、税费、运费、舍入规则都显示在预览中；保存前要求用户确认。
- 生成后固定该报价版本的输入和计算结果；后续价目表更新不应悄悄改变旧报价。

## 验收条件

- 可建立含多产品行的草稿，编辑后重新打开数据完整。
- 数量、单价、折扣及费用的服务端计算和 PDF 汇总一致，支持零值和边界输入校验。
- 未确认价格或关键客户信息时，明确提示；可保存草稿但不能误显示为已确认报价。
- PDF 中文字体正常、页码/分页可读，下载名称含报价单号；生成后可再次下载。
- 删除或复制报价行为明确；资料来源可点击回到本地文件。
- 在本机和 Docker 部署使用相同的数据目录配置，项目搬到 NAS 后报价草稿和 PDF 可一起迁移。

## 开发顺序与需要的业务资料

1. 先实现 MVP：数据库迁移、报价 API、编辑/预览页面、PDF 中文排版、草稿列表。
2. 接入已索引资料的产品选择与来源展示。
3. 加入价目表导入、PI 和运费规则。

开始实现前需要确定公司抬头/Logo、常用语言、币种、默认贸易及付款条款，并提供实际商品报价表。运费功能再提供运费表和计费规则；PI 阶段提供现用 PI 模板或确认使用新模板。没有这些资料时，MVP 可以先允许手工填写并在 PDF 中标记由用户确认。
